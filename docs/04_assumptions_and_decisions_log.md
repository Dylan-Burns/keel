## 4. Assumptions and decisions log

This log records 36 decisions and 15 assumptions. Each decision names at least 1 alternative, the reason for the choice, and the cost to reverse the choice. Each decision also names the panel answer that changes the choice. The IDs appear in the other chapters.

### 4.1 Decisions

| ID | Decision | Alternatives considered | Rationale | Reversibility | Panel answer that changes it |
| --- | --- | --- | --- | --- | --- |
| D-01 | The answer call is the only LLM generation. Question embedding, lexical search, metadata filters, a local cross-encoder reranker, and code-based citation validation do not count as the answer call. | Count every model call, even embeddings. Permit a second LLM call for verification. | The brief says the answer must come from 1 LLM call and leaves the pipeline open. An embedding model and a cross-encoder do not generate text. | High. A config flag turns the reranker off, and lexical-only retrieval works without embeddings. | An embedding call counts as an LLM call. Then Keel runs with lexical retrieval only. |
| D-02 | Keel does not use an LLM at index time. | LLM summaries per section at index time. | D-03 | Keel discloses every pre-call step to the panel on the architecture slide. | Mention only the single call. | The brief invites questions. Full disclosure removes the risk of a late objection. | Not applicable. | None. |
| D-04 | A failed request that returns no answer does not count as the answer call. The adapter retries up to 2 times on transport errors, rate limits, and 5xx errors, and never after the stream has started to deliver content. | No retries. Retry after partial output. | The answer still comes from 1 completed request. A partial answer followed by a retry is 2 answers, so the design closes that path. | High. Set `max_retries` to 0. | Any second request is a violation. Then set `max_retries` to 0 and show the error. |
| D-05 | Python 3.12 with FastAPI and uvicorn. | Flask, Django, Node with Express, Go with chi or Gin. | Native async streams, pydantic schemas, and type hints. The brief lists this default. The whole service. | The firm requires another language. |

| D-07 | The embedding model is BAAI/bge-small-en-v1.5 (384 dimensions, 512-token input), pinned to a revision hash. | bge-base, nomic-embed-text-v1.5, all-MiniLM-L6-v2, a hosted embedding API. | Fast on a CPU inside the timebox with good English retrieval quality. | D-08 | The dense index is a flat NumPy matrix of float32 unit vectors with cosine similarity over masked candidates. | D-09 | Fusion is reciprocal rank fusion with k = 60 and equal weights. | Weighted score sum with min-max normalization. Lexical only. Dense only. | Robust to different score scales with 1 parameter. The ablation in chapter 18 measures the gain. | High. Config. | None. |
| D-10 | The reranker is cross-encoder/ms-marco-MiniLM-L-6-v2 over the top 80 fused candidates, on by default. | bge-reranker-base. No reranker. | D-11 | The model is Claude Sonnet 5.5, pinned to the dated snapshot identifier. The fallback model is Claude Haiku 5.5, also pinned. | Opus 5.5 for quality. Haiku 5.5 only for cost. Another provider. | Long-context synthesis quality at about $0.09 per question. Stage 0 note: the models list has no dated identifier for the 5.5 models, so the pins are the plain ids `claude-sonnet-5-5` and `claude-haiku-5-5` (the data wins). | High. Adapter and config. | The firm prefers another provider. Then write a second adapter. |
| D-12 | Temperature is 0 and the output limit is 4,000 tokens. | The default temperature. | Reproducible retrieval plus stable output, and fewer invented details. | High. Config. | None. |
| D-13 | The answer comes as structured JSON through a JSON schema. The adapter requests the provider's structured output. | D-14 | The service streams the answer with server-sent events (SSE). | WebSocket. A poll loop. | One direction, simple, and works through proxies. | High. | None. |
